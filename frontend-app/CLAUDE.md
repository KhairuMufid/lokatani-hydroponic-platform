# PROJECT OVERVIEW
Project: Lokatani - Smart Hydroponics Pest Detection Platform (Frontend)
Role: You are an Expert UI/UX Designer and Lead Frontend Architect.

# THE CORE CHALLENGE (DUAL PERSONA & HARDWARE INTEGRATION)
You must design and architect a React application that balances two conflicting identities:
1. **The Agritech Product:** For hydroponic farmers. It must be a beautiful, modern, and intuitive monitoring platform. Features include viewing system health, monitoring live cameras, historical detection logs, and immediate Decision Support System (DSS) mitigation steps. Technical jargon must be hidden.
2. **The Thesis Experiment:** For the software engineering researcher. Underneath the UI, this application measures Quality of Service (QoS) across different network protocols (HTTP, WebSocket, MQTT). The researcher needs a way to switch protocols and view raw latency/throughput metrics.

*Hardware Context:* The live stream data is generated by a physical **Raspberry Pi equipped with a Camera Module** acting as the IoT edge node. The frontend must be resilient enough to handle real-world network jitter, dropped frames, or temporary disconnects typical of physical wireless hardware.

# THE ENGINEERING BOTTLENECK (15 FPS DATA FIREHOSE)
The backend streams real-time telemetry and Base64 encoded images originating from the Raspberry Pi at up to **15 Frames Per Second (15 FPS)**. 
- *The Problem:* Standard React state updates for a 15 FPS image feed will cause massive reconciliation overhead, memory leaks, and a frozen UI. 
- *Your Task:* Architect a high-performance rendering strategy that neutralizes this bottleneck while keeping the rest of the application responsive.

# SYSTEM REQUIREMENTS & PAGES
Design a seamless navigational experience encompassing at least the following modules:
1. **Dashboard:** High-level system overview, recent alerts, and environmental summary.
2. **Live Monitor:** The core real-time view where the 15 FPS video feed from the Raspberry Pi and YOLO bounding boxes are displayed alongside dynamic DSS actions.
3. **Reports/Logs:** A historical view of past detections.
4. **Settings:** User configurations. *Crucially, this is where the Thesis Experiment controls (Protocol Switcher & QoS Metrics) should be cleverly integrated so they don't disrupt the farmer's experience.*

# BACKEND INTEGRATION & CODEBASE CONTEXT
The workspace root contains the `backend-app` directory, which is the fully functional backend for this project.
- **Analyze the Backend:** You MUST read the codebase in `../backend-app` (controllers, gateways, and DB schema) to understand the exact JSON payload structures, endpoints, and MQTT topics.
- **Backend Adaptability:** If your frontend architecture requires additional REST endpoints, modified WS broadcast logic, or new data aggregations to support the Dashboard or Reports pages, **you are expected to propose those backend modifications**.
